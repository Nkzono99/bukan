# Bukanアプリで研究を進める

Bukanを開き、調べたい問いをCodexに伝え、蓄積されたノートと根拠を確認する。この往復を同じアプリ内で行います。文献管理、研究記録、Codexとの対話は別の役割を持ち、同じ研究ワークスペースを参照します。

研究wikiでは、テーマや問いごとの同じ項目を継続して改訂します。[研究wikiの設計と実装範囲](research-wiki.md)に全体構成を、[情報の階層と詳細度](research-knowledge-layers.md)に原資料・論文ノート・wiki・対話の役割をまとめています。概観から条件別の比較、詳しい読解と原図へ進める構成にします。

Codexへ渡す指示と、コードで検査する範囲は[研究ハーネス](research-harness.md)を参照してください。新しい研究フォルダには作業別のSKILLを同梱し、今回の依頼に必要な手順だけを読みます。

## 最初に行うこと

1. 「研究を開く」で、`bukan.toml`のある研究フォルダを選びます。ダスト輸送の既存データを使う場合は、`C:\Users\hnjm4\Documents\BukanResearch\dust-transport`です。新しいテーマは「新しい研究」で保存先を作ります。
2. 「研究wiki」の準備ボタンを押します。アプリに同梱した研究エンジン用に、Pythonと固定バージョンの依存パッケージを取得します。初回はインターネット接続が必要です。準備前でも保存済みのレポートを読めます。既存の形式1のDBでは「バックアップして移行」から形式2へ更新します。以後は形式2に対応したBukanを使います。
3. Codex CLIを利用できる状態にして、アプリ内のCodexを開きます。Codexのインストールとアカウントへのログインは別途必要です。初回にフォルダの信頼確認が出たら、表示された保存先を確認して進めます。Bukanは利用可能なCLIを検出し、この研究に対応する文献管理MCPと研究MCPを起動時に登録します。

研究エンジンのソースコードを別途チェックアウトしたり、利用者がPythonの仮想環境やMCP設定を組み立てたりする必要はありません。Windowsで環境作成用の`uv`がない場合は、準備操作からWindows Package Managerで取得します。

研究wikiで項目を開き、必要なら「この節を調査対象にする」を押します。「この項目から調査を続ける」に問いと調査条件を書きます。例えば次のように依頼します。

> ダスト輸送について、粒子が表面から離脱する条件に関する主張を比較して。既存ノートと作業記録を確認し、引用先・被引用文献・引用関係のない関連研究を追って。未読論文は文献ごとのサブエージェントで全文を読み、重要な解釈は別担当で検証して。条件が異なる結果は分けて整理し、未取得論文と残る課題も更新して。

「依頼を保存してCodexを開く」を押すと、依頼と閲覧中の資料への参照を保存し、Codexを併設します。表示された引き継ぎ文をコピーし、Codexの入力欄へ貼り付けて送信してください。保存ボタンだけでは解析は始まりません。以後の指示、確認、追加の相談は同じCodex欄で続けます。

人間は問いの優先順位、調査範囲、入手費用、実験・解析の制約を伝え、研究の判断に関わる主張と原図を確認します。Codexは既存記録を再利用し、文献取得、全文レビュー、独立した検証、論文間の比較を分担して進めます。詳細な手順は[網羅的な先行研究解析](exhaustive-review.md)と[並列レビュー](parallel-review.md)に従います。

wikiの項目から依頼すると、研究DBにも対象ページ・節を指定した作業を保存します。Codexは同じ作業記録に担当、途中経過、結果を残します。引き継ぎに失敗しても、保存済みの作業は「調査待ち」から確認できます。

## 結果を読む・直す

| 画面 | 用途 |
| --- | --- |
| 研究wiki | 項目を検索し、階層、比較、採用した根拠、改訂履歴をたどる。調査待ちと未統合候補を確認する |
| 研究記録 | 問い、論文、文献ノート、主張、根拠、関係、作業記録を検索する。参照先の記録をたどる |
| ノート・レポート | `notes/`、`reports/`、`queries/`、`candidates/`の文書を選んで読む。未取得文献のBibTeXも参照する |
| ライブラリ | 同期済みのPaperpile文献を探し、PDFを読む |
| 継続レビュー | テーマ別に作成したレビューを改訂し、Codexへ更新対象を伝える |

本文はMarkdownとして表示し、`$$`の数式、表、埋め込み画像に対応します。文書間のリンクや原PDFへのリンクから確認を続けられます。表示件数は保存された記録の数であり、読了率や検証済み件数ではありません。未統合候補には論文だけでなく、新しい本文取得記録や主張なども含まれます。各記録の状態と根拠を確認してください。Codexが更新した結果は「更新」で読み直します。

wikiはページ内の節ごとに編集できます。保存すると新しい改訂を作り、変更した節の以前の点検結果は引き継ぎません。根拠の新版が見つかった節は、解釈の再検討対象として表示します。追加調査では全文ノートと比較結果を再利用し、同じwikiへ反映するか、変更しない理由を作業記録へ残します。節の根拠や分類を構造化して変更する場合は、Codexから研究MCPを使います。

研究記録の文献ノートを編集して保存すると、研究DBに新しい改訂を作り、検索にも反映します。既存の根拠や読解状況は保持しますが、追記した解釈が自動で科学的な検証を通るわけではありません。重要な訂正はCodexにも伝え、対応する主張・根拠・比較記録を更新します。

通常のMarkdownレポートの編集は、そのファイルと変更履歴へ保存します。DBへの取り込みはCodexへ依頼します。`data/paper-notes/`の書き出し済みノートは改訂スナップショットなので、研究記録の編集機能から新しい改訂を作ります。保存時に他の更新が見つかった場合は、下書きを保持して照合を求めます。未保存の下書きはアプリ内の画面切り替えでは保持しますが、アプリ終了前に保存してください。

## 保存先と役割

| 内容 | 保存先・担当 |
| --- | --- |
| 受け入れ済み文献・原PDF | Paperpile / Google Drive。Bukanは読み取り専用 |
| 研究の構造化記録 | 開いた研究の`data/research.sqlite`。研究エンジンが管理 |
| wikiの改訂と図表付きMarkdown | DBに本文・画像の固定改訂を保持し、`data/wiki/`へ書き出す。著者入力時の画像は`data/wiki-assets/` |
| ノートの改訂と図表 | `data/paper-notes/`、`data/note-assets/`など。同じ研究に保持 |
| 人間が読む成果物 | `notes/`、`reports/`など |
| 保存した調査依頼 | `queries/requests/`。現在の引き継ぎ先は`.bukan/current-research.md` |
| 研究エンジンの実行環境 | BukanのAppData。研究データとは別に管理 |

ダスト輸送のデータもこの通常の保存方式で扱います。2026年9月15日に既存DBを形式2へ移行し、13ページ・78節のwikiを登録しました。Markdownから読む入口は研究フォルダの`notes/wiki-index.md`、移行前DBのバックアップ先は`data/wiki-migration.json`に記録しています。バックアップは研究フォルダ全体を対象にします。SQLiteをコピーする場合は、書き込みを止めるかSQLiteのバックアップ機能を使います。

MCPは文献や研究記録へアクセスする窓口です。対話とサブエージェントの実行はCodexが担当し、並列数やモデルはCodex側の設定と利用可能な実行枠に従います。Bukan自身が、アプリを閉じても動く研究ジョブを提供するわけではありません。再開時は保存済みの作業記録をCodexに確認させます。

Google Driveが未接続でも研究フォルダを開けます。保存済みのノートやレポートを読み、原PDFが必要な場面でDriveを再接続してください。PDF本文・ページ画像の取得には、[PDF読解の使い方](full-paper-reading.md)に記載したPopplerが必要です。
