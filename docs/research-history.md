# 研究課題の変遷と、次に取得する文献を残す

研究史は、各論文を「その時点の問いに、どの条件で、どこまで答えたか」で整理します。
論文別の全文ノートを根拠にし、後続論文による拡張・批判・条件変更を結びつけます。
研究テーマを提案するときは、未読文献による空白と、読んだ文献が示す未解決事項を区別します。

このプロジェクトの標準は、網羅的な探索と主張単位の詳細解析です。引用の前後への反復探索に加え、
非引用の関連研究も独立に探します。研究史は蓄積した詳細解析の閲覧用の一つの形です。
探索キュー、関係ごとの詳しい比較、網羅性の記録と再点検は[網羅的な先行研究解析](exhaustive-review.md)に従います。

## 保存先と研究MCPの役割

成果物はユーザーの研究ワークスペースへ保存します。

| ファイル | 用途 |
|---|---|
| `reports/<theme>-research-history.md` | 課題別の年表、後続研究との関係、研究案 |
| `data/research-history.json` | 根拠と版を固定したイベント・関係・残課題の構造化記録 |
| `candidates/literature-access.bib` | 必要な未取得文献と代替版の確認対象。Paperpileへの登録前の候補 |
| `candidates/literature-access.json` | アクセス確認、代替版、優先度、取得・読解状態の記録 |
| `candidates/literature-access.md` | 購入等を検討するときに読む一覧 |
| `queries/<date>-research-history.md` | 探索範囲、情報源、検索式、採否と探索の限界 |

このJSONは、既存SQLite形式1を変更しない独立した文書形式です。どちらも
`format_version: 1`と調査基準日を持たせます。破壊的に構造を変える場合は文書形式の版を上げます。
今のMCPはこれらのファイルを自動で取り込みません。検索の入口として研究史の短い概要を
`Topic.scope`へ保存し、`members`から対象のPaperNote・Claim・Questionの固定改訂へ結びます。
詳しい年表はMarkdownとJSONに置き、検証した新しい知見は通常のClaim・Evidenceとして登録します。
未読候補の題名や要旨から研究上の結論を登録しないでください。

## 年表に残す単位

`data/research-history.json`は`scope`、`papers`、`themes`、`events`、`links`、
`open_questions`、`discovery_backlog`を持つ形を基本とします。

- `papers`：論文ID、対象版、ノートの改訂、本文Sourceの改訂、PDFハッシュ、ページ数、読解状態。
- `events`：安定したID、問いのID、年・日付と精度、論文参照、その時点の問い、貢献、実証の種類、成立条件、残された限界、根拠。
- `links`：接続元・先のイベント、関係、後続研究での扱い、引き継いだ条件と変更点、根拠。
- `open_questions`：何が未確定か、今回の資料内の限界か分野の未解決問題か、判別に必要な文献・実験、現在のQuestion参照。
- `discovery_backlog`：未読の関連文献IDと、どの歴史上の判断に必要か。アクセス台帳の候補キーと対応させる。

根拠は`id`と`revision`の固定参照に加え、PDFファイルページ・図表番号を持たせます。
必要ならSource内の正確な文字範囲も保持します。後からノートが改訂されても、年表が
どの根拠で作られたかを追えるようにし、新版を取り込むときは判断の変更理由を残します。

「どれくらい解明できたか」は、機構の提案、条件付き計算、実験による支持、観測上の制約などと、
対象の粒径・材料・照射・重力・測定量で表します。根拠のない達成率は付けません。
後続論文が明示する引用・拡張は`author_explicit`、読み手による概念的な比較は
`analyst_inference`として分けます。単なる引用と、モデルを実際に継承したことも区別します。

発表年、初回オンライン公開、プレプリント版、観測の実施時期を混ぜません。
同年の論文を公開順に並べただけでは影響関係を確定できません。研究史の空白を
「その後は研究されなかった」「解決済み」「世界初」と言い換えないでください。

## 全文が取れない論文も次の判断につなげる

取得は**Google Drive／Paperpile → 出版社 → プレプリント・著者公開版 → 未取得台帳**の順で進めます。
最初にBukanの読み取り専用索引を調べます。DOIが索引にない場合は題名・著者でも探し、実PDFの版と
ハッシュを確認します。Driveの取得失敗や索引未更新を未所蔵と同一視せず、確認できない段階はそのまま記録します。
外部サイトで取得できなくても、所蔵済みと分かれば購入候補から外します。

DOIで重複を照合し、DOIがない場合は題名・著者・年・他の永続IDを確認します。
BibTeXは出版社や機関リポジトリで確認できたフィールドだけを入れます。
台帳のキーとBibTeXキーを一致させ、必要な理由と次の行動をMarkdownへ記します。
自動出力の`data/paperpile.bib`や同期済みPDFには書き込みません。

取得状態、読解状態、購入判断は別々に記録します。PDFリンクを発見しただけでは取得済みではなく、
ダウンロードしただけでは読了ではありません。HTTP 403、bot対策、ログイン要求、リンク切れを
有料と断定せず、明示された購読・購入制限と分けます。確認日と実際に試したURLを残します。

出版社公開版、著者の公開原稿、機関リポジトリ、arXiv等を確認します。全文のプレプリントや
著者最終稿は、対応論文と版を確認して代用できます。出版版が見られない場合は同等性を未確認とし、
重要な式・図表・結論、補足資料、訂正の差分を確認する作業を残します。
会議要旨やスライドを雑誌論文の全文と同一視しないでください。

台帳には少なくとも、`key`、書誌、必要な理由、優先度、取得・読解状態、確認日、
`attempts`（URL・結果）、`alternatives`（URL・版・同定の根拠・代用判断）、
`next_action`、`purchase_decision`を記します。見つからない代替版は「今回の探索では未発見」とします。
価格・購入済み・機関契約の有無を推測で埋めません。取得できたら同じ候補を更新し、版・ハッシュを
確認して全文レビューへ渡します。候補への掲載はPaperpileへの登録承認や購入承認を意味しません。

## 作業は文献別の読解と課題別の比較に分ける

既読の同じ版のノート・抽出キャッシュを再利用し、新規文献だけ全文レビューへ回します。
文献別の読解担当と、取得可能性を調べる担当は並列に進められます。根拠を確認したノートが揃ったら、
課題別に歴史の比較を分担し、調整役が条件差と相反する所見を統合します。
共有の年表・台帳・Questionは調整役が更新し、作業者同士の上書きを防ぎます。

最終確認では、年表の根拠参照、日付・版、直接の継承と推論の区別、未読資料からの結論混入を点検します。
画像は文書配下へ同梱して埋め込み、数式・プレビューの確認には[全文読解](full-paper-reading.md)と
[並列レビュー](parallel-review.md)の手順を使います。対象プレビューを開けない場合は確認範囲を記録します。
