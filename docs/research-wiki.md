# 学問の項目を育てるBukan研究wiki

Bukanの主な成果物を、同じ項目を継続して改訂する研究wikiにする。分野の大規模レビュー論文に相当する網羅性と詳しさをwiki全体で目指し、概観、論点別レビュー、条件別比較、導出・原資料の確認へ階層化する。追加サーベイでは、影響する項目の解釈・比較・未解決事項を更新する。

**状態：初期実装。** 形式2の研究DBにwikiのページ・節・固定根拠・作業・未統合候補を保存する。アプリの閲覧・編集・履歴・検索、根拠変更の検出、画像付きの改訂出力、バックアップ付きの形式移行を実装した。現在の操作は[アプリの利用手順](app-research.md)を参照。

以下には継続する設計目標も含む。現在の比較表は根拠を付けたMarkdownで、共通の比較定義から表を自動生成する機能、値・単位による検索、意味検索、名称変更の転送先は未実装である。新資料の関連項目候補は題名・別名・分類の文字列照合で提示し、科学的な関連性は担当が判断する。

wikiを現在の解析・解釈の正本とし、原論文、文献ごとの読解記録、構造化した根拠も保持する。論文Markdownは再利用できる中間成果で、毎回の要約レポートを重ねる必要はない。各層の役割、削減する複製、対話へ渡す情報、詳細度の基準は[情報の階層とレビューの詳細度](research-knowledge-layers.md)で定める。

## 攻略wikiから、項目・比較・相互参照の構造を取り入れる

参考にしたwikiでは、対象ごとの定型情報、仕組みの説明、他の対象との比較を行き来できる。下表の右列は、それをBukanに適用する設計判断である。ゲーム内の数値や文章は転載しない。

| 参照した構造 | Bukanでの使い方 |
| --- | --- |
| Factorio Wikiの個別設備ページは、諸元、必要技術、他設備との出力比較、変更履歴、関連項目をまとめる。[Electric furnace](https://wiki.factorio.com/Electric_furnace) | 理論や手法のページに、前提、入力、予測・出力、他手法との比較、研究史をまとめる |
| Stardew Valley Wikiの作物一覧は、成長や収益の比較に使う前提を説明し、個別項目や用途へ接続する。[Crops](https://stardewvalleywiki.com/Crops) | 比較表の上に対象条件・定義・計算方法を表示し、各値から原論文の根拠へ移動できるようにする |
| PoE Wikiは、テンプレートで個別項目の情報を登録し、その情報から一覧表や他ページの情報欄を作る。[Help:Templates](https://www.poewiki.net/wiki/Help%3ATemplates) | 条件、値、根拠を一度登録し、個別解説・比較表・参照先で再利用する |

学問では、後年の論文が前の論文を一律に置き換えるとは限らない。複数の説明が条件ごとに成り立つ場合もある。そのため、各記述に適用範囲と根拠を付け、対立や留保を残す。検索順位、被引用数、発表年から知見の確かさを決めない。

## 人間は項目を読み、その場から調査を依頼する

Bukanを開くと研究wikiの入口を表示する。例えば「ダスト輸送 → 表面からの離脱 → 照射条件の比較 → 該当する原図」とたどり、気になった段落から「この説明の根拠を検証」「この条件の先行研究を追加調査」と依頼する。

| 画面の場所 | 表示する内容 |
| --- | --- |
| 研究の入口 | 対象範囲、主要項目、現在取り組む問い、解釈が変わった箇所、未統合の資料 |
| 左の案内 | 分野・項目の一覧、別名を含む検索、条件別の比較、研究史、調査待ち |
| 中央の本文 | 現在版の解説、条件、式、図表、比較、残る問題。詳細解析まで展開して読める |
| 根拠の欄 | 選んだ記述の支持・反対の証拠、引用箇所、原PDF、参照元のページ |
| 対話の欄 | 選択したページ・節・条件を引き継ぐCodex。進行中の依頼と保存済み作業も確認する |

狭い画面では根拠と対話を切り替えて開く。本文の「読む」「編集」「変更履歴」から日常の操作を行い、読者にDBのIDや内部の改訂番号を入力させない。手動の更新操作は残し、取得できていない更新を表示済みと扱わない。

検索は項目名・別名・本文・主張を対象にし、分野、現象、方法、条件、根拠の種類で絞る。標準結果は各項目の現在版で、旧版や調査ログは別に選べる。検索基準日や再検討の表示を伴う結果にする。意味検索は後から足せるが、最初から利用可能とは扱わない。

## 項目の種類を揃え、複数の入口から同じ内容へ接続する

ページ名は原則として対象や問いの名前にする。「2026年9月の追加調査」は調査ログへ置く。同じ対象を扱うページを更新し、名称変更後も固定ID、別名、転送先からたどれるようにする。

| 項目の種類 | 固有の内容 | ダスト輸送での構成例 |
| --- | --- | --- |
| 分野・テーマ | 範囲、項目地図、用語、主要な問い、隣接分野 | ダスト輸送、月面環境での輸送 |
| 概念・現象 | 定義、判定方法、混同しやすい概念、発生条件 | 帯電、離脱、浮上、移動、輸送 |
| 理論・モデル | 仮定、式、導出、予測、適用範囲、実測との対応 | 帯電モデル、付着力モデル、運動モデル |
| 手法 | 入力、装置・手順、測定量、分解能、誤差、再現条件 | 粒子追跡、電荷計測、数値シミュレーション |
| 対象・資料 | 材料・環境・データセットなどの性質と来歴 | 模擬試料、実験環境、観測データ |
| 問い・論争 | 現時点の回答、競合する説明、両側の根拠、判別に必要な研究 | 観測された運動から何を結論できるか |

この例は分類の案であり、科学的な結論を示すものではない。論文ページは既存の書誌・全文ノートを表示する根拠資料の入口として持つ。研究史、比較表、用語一覧は上の項目に結び付く閲覧方法で、全文を別々に複製しない。長い比較や論争には独立した固定IDを与え、複数ページから参照する。

一つの項目は複数の分野に属してよい。階層は案内用とし、例えば「付着力」を材料・接触・離脱のどの入口からも開けるようにする。別名には言語、旧称、略語とその適用範囲を持たせ、同じ語に異なる意味がある場合は候補を提示する。題名の類似だけで統合しない。項目の分割・統合では旧IDと旧節へのリンクを保存し、分割先が複数なら案内ページを残す。

物理の項目に使う「粒径・照射・測定誤差」を、他分野の全ページへ強制しない。共通部分は問い・根拠・条件・解釈・履歴とし、数学なら定義・仮定・証明、歴史研究なら史料・時期・解釈などを種類別の書式で補う。論文以外の一次資料を扱う拡張では、現在のPDF読解とは別に資料固有の確認記録を設計する。

## ページは、現在の理解から詳細な検証へ読めるようにする

冒頭で対象、現在の理解、主な留保を短く説明する。その直下に対象条件、調査の基準日、最終検証日、未読・未取得資料への入口を置く。短い説明から、条件別の結果、導出、論文間の比較へ読み進められる構成にする。

| 本文の部分 | 記載する内容 |
| --- | --- |
| 定義と範囲 | 何を扱い、どの意味・条件で使うか。近接する概念との違い |
| 現在の理解 | 根拠付きの解釈、適用条件、重要な留保 |
| 機構・導出・手順 | 理論の仮定、式の記号と単位、導出、方法の詳細 |
| 条件別の比較 | 結果とその根拠、比較可能な範囲、比較できない理由 |
| 対立と限界 | 説明が一致しない箇所、反対の証拠、代替説明 |
| 研究の発展 | その時点の問い、各研究が示した範囲、後続研究での扱い |
| 残る課題 | 調査不足、資料不足、研究上の未解決事項、次の検証 |
| 関連項目 | 前提になる概念、同じ方法、別条件の結果、この解釈に依存する研究案 |

これは内容の共通書式であり、全ページに空の見出しを並べる要件ではない。根拠のない節は作成待ちとして一覧に出し、検証可能な内容から整備する。重要な説明を要約する場合も、詳しい比較・計算・原文位置へ接続し、既存の詳細を消さない。

各節と、根拠を付ける判断に固定IDを持たせる。著者が報告した結果、著者による説明、wikiの読解担当による統合的な解釈、人間の研究案を区別する。ある解釈を採用した理由と、それに反する証拠の扱いを同じ場所で読めるようにする。

数式は独立した行の`$$`で囲む表示形式を標準にする。重要な図表はPDFから切り出して本文へ埋め込み、論文・版・PDFページ・図表番号・切り出し範囲を保持する。複数パネルを切り離した場合も元の文脈へ戻れるようにする。画像は各書き出し文書の配下へ同梱し、BukanとVS Code標準プレビューで確認する。

## 比較する単位は、条件と根拠を持つ個々の結果にする

一つの論文に複数の実験やモデルがあれば、比較表には別の行として載せる。「A論文：支持、B論文：反対」だけでは、何が一致し何が異なるかを検討できない。

比較に使う結果には、対象、観測量の定義、方法、条件、値と単位、不確かさや測定限界、著者の解釈、根拠位置を持たせる。換算した値には元の表現と変換式を残す。記載なし、未確認、該当しない、検出限界未満を区別し、空欄やゼロへまとめない。

例えば「離脱条件」の比較書式には、試料、粒径の定義、接触状態、照射、環境、観測量、結果、判定の限界、出典を用意する。これは入力項目の例であり、実データは各論文の確認後に登録する。条件が揃わなければ行を分け、条件の違いを明記する。

同じ比較記録から個別ページと一覧表を表示する。本文に採用した表は、行ごとの固定改訂と比較条件を保存する。新しく検索に掛かった結果は「未統合の候補」に出し、表だけが自動で増えて本文の解釈と食い違う状態を避ける。

複数論文が同じデータや装置に依存している場合、その共有も記録する。引用件数を独立した検証の数として数えない。比較の並び替えは読者が条件と観測量を選んで使うもので、理論全体に一つの優劣順位を付けるものにはしない。

## 根拠の状態、検証の状態、調査範囲を分けて表示する

「検証済み」は真理の認定として使わず、どの担当が、どの資料・記述を、何について点検したかを示す。新しい論文や証拠で再検討できる記録にする。

| 表示する軸 | 内容 |
| --- | --- |
| 根拠の性質 | 観測、実験、計算、証明、史料の解釈、仮定など。分野に応じた分類 |
| 結果同士の関係 | 支持、拡張、反対の証拠、条件差、判断保留。対象となる具体的な主張を指定 |
| 点検の状態 | 未検証、独立点検済み、指摘未解消。担当、対象改訂、所見を併記 |
| 更新の必要性 | 根拠の変更、訂正、新資料の未統合、検索期間の不足とその理由 |
| 探索の範囲 | 検索式・情報源・期間、確認した候補、全文読了、未取得・未読・比較待ち |

読了、引用箇所の一致、科学的な妥当性の点検は別の状態である。本文の書き換えで判断や根拠が変われば、以前の点検結果をそのまま継承しない。共通の数値スコアで「信頼度95%」などと表示せず、根拠と限界を提示する。

未解決事項は「まだ調べていない」「必要資料が取れていない」「確認した資料では答えが出ていない」に分ける。分野全体で未解決だとする判断にも探索範囲と根拠を付ける。網羅性の件数には分母と基準日を併記し、対象分野の全論文数が不明な場合は分野全体の達成率を出さない。

## 追加サーベイを、既存ページの更新として完了させる

依頼には対象ページ・節・条件、調査の目的、基準日を記録する。「新着論文を探す」「過去の探索漏れを埋める」「一つの主張を再検証する」を選べるが、自然文だけでも既存の項目との対応を確認して進められる。

1. 既存ページ、固定された根拠、検索表、未処理候補、未解消の指摘を読み、更新対象を決める。
2. 引用・被引用と独立検索を並行して進め、新しい呼称、隣接分野、反例も探索する。新着だけを追加調査の対象にしない。
3. Google Drive／Paperpile、出版社、プレプリント等の順に取得する。取得できなければ理由付きで既存のBibTeX台帳へ追加・更新する。
4. PDF版を照合して既読成果を再利用し、未読文献は論文ごとのサブエージェントで全ページを読む。主張・条件・根拠・関係の候補を保存する。
5. 候補と既存の解釈を比較し、変わる節、維持する節、新設する項目を特定する。結論を左右する箇所は別担当が原資料へ戻って点検する。
6. 統合担当が人間の追記と各担当の結果を照合し、関連ページと比較記録を改訂する。保存直前にも入力の改訂を照合する。
7. 変更理由、判断を維持した理由、未統合の候補、残る作業、次に再開する位置を保存する。

探索・取得・読解・比較・監査を別の作業として進め、依存する成果が揃った順に渡す。並列担当は個別の成果と変更案を返し、同じページへの統合は一人の担当が行う。独立したページは別担当で更新できる。競合時は差分を読んで統合し、人間の変更を上書きしない。中断後も担当と保存済み成果を確認して再開する。

依頼は、対象ページごとに「改訂済み」「比較の結果、変更不要」「理由付きの未完了」を記録して閉じる。未完了がある依頼を、ノート作成だけで完了と表示しない。回ごとのレポートはこの更新の要約として任意に出力する。

探索の反復と終了判定は[網羅的な先行研究解析](exhaustive-review.md)、読解の配布は[並列レビュー](parallel-review.md)を引き継ぐ。wikiへの整理を理由に、全文読解や詳細な関係解析を省略しない。

## 根拠の変更を依存先へ伝え、新しい証拠も拾う

ページ間のリンクには二つの役割を持たせる。案内用リンクは現在版へ移動する。判断を支える参照は、記録と改訂、必要なら節を固定する。過去版の再表示では、当時使った根拠を保つ。

既存の根拠が改訂されたら、それを使う節と、さらにその解釈を使うページを逆向きにたどる。再検討が必要な理由と伝播経路を表示し、確認する作業を作る。単なる関連項目リンクで全ページを再検討扱いにしない。循環する参照には訪問済みの判定を使い、互いのページだけを根拠にした循環論証も点検する。

一方、新しい論文には既存ページとの参照がまだない。依存先の追跡に加えて、登録時に概念、方法、条件、問いを照合し、関連しそうなページの候補へ入れる。候補の提示と科学的な関連性の確定を分け、採否を担当が記録する。用語が異なる研究は独立検索で補い、関連付け待ちの資料も一覧から確認できるようにする。

SourceとEvidenceは現在の実装では同じIDのまま変更できない。PDF新版、訂正、撤回などは別の取得記録と対応関係として登録し、それを用いた主張へ検討を戻す。名称やハッシュの一致だけで版の同等性を決めない。

更新に関係する日付は、研究・出版の日付、wikiの編集日、根拠を点検した日、探索で確認した期間の終端を分ける。今編集されたページでも、探索が過去の期間までならその範囲を表示する。根拠の新版があることだけで古い結果を誤りと認定しない。

## 既存の研究DBを土台に、wikiの解釈を保存する

編集する研究記録とwikiの正本は、外部研究ワークスペースの`data/research.sqlite`に保存する。原PDFは出典として別に保持する。Bukanのアプリ、研究MCP、CLIが同じ研究記録を読み書きする。管理されたMarkdownは現在版と固定改訂の出力とし、独立した手書きノートは取り込み前の原本として保持する。編集の取り込みでは元の改訂と人間の差分を確認する。

現在の`Topic`は題名・範囲・メンバー参照を持つ。`PaperNote`は一つの資料の読解に対応する。この二つを保持し、横断的な解説には新しい`WikiPage`を加える。ページの種類ごとに別DBや別の保存方式を増やさない。

| 保存する単位 | 設計上の内容 |
| --- | --- |
| `WikiPage` | 固定ID、題名、別名、種類、範囲、分類、節、案内リンク、変更理由 |
| ページ内の節・判断 | 固定ID、Markdown本文、解釈の出所、支持・留保・反対の根拠への固定参照、点検記録 |
| 種類別の情報欄 | 定義、条件、入力・出力など。項目名、値、単位、記載状態、根拠を保持する共通形式 |
| 比較の定義 | 比較軸、対象条件、採用する結果・関係の固定参照、換算方法、表示順 |
| 案内と依存の索引 | 案内先、固定根拠、逆参照。保存内容から再構築できる索引 |

論文の主張は既存の`Claim`と`Evidence`、主張同士の比較は`Relation`を使う。wikiの統合的な解釈は節・判断として根拠を明示し、著者が述べた主張へ混ぜない。研究案は`Question`へ接続する。同じ比較を複数ページで使う場合は一箇所に定義し、採用した改訂を参照する。

初期段階は、既存の条件付きClaim・Relationを比較表の行に使える。値や単位の厳密な絞り込みを実装する段階で、対応する項目定義と検査を追加する。自由文の条件辞書を、既に数値検索できるデータとして扱わない。

本文中の根拠参照と構造化した参照は、保存時に対応を検査する。前者だけに出典を追加したり、後者だけを新版へ差し替えたりした場合は未解消として扱う。固定参照から作る比較表の行集合も記録し、過去のページを同じ根拠で再表示できるようにする。

再検討の通知と作業状態は本文の改訂とは分ける。人間の編集は保存できるが、その編集をAIによる独立点検済みとは扱わない。調査担当の変更案と監査所見は保存してから統合し、確認待ちの解釈を表示するときはその状態を明記する。

### アプリ・MCP・Codexの役割

| 担当 | 行うこと |
| --- | --- |
| Bukanアプリ | wikiの閲覧・編集・比較・検索、原資料の確認、対象を指定した調査依頼 |
| 文献管理MCP | 書誌とPDFへの読み取り専用アクセス、全文・ページ画像の取得 |
| 研究エンジン／研究MCP | ページと根拠の保存、構造検査、改訂競合の検出、依存先・未処理事項の取得 |
| 対話中のCodex | 探索計画、読解担当の配布、科学的な解釈、独立点検、ページへの統合 |

`get_record`、`put_records`、`get_history`はwikiレコードにも対応する。`research_wiki_request`でページ表示、wiki検索、逆参照、作業・更新候補を扱い、`export_wiki_page`で固定改訂と図表を書き出す。操作名と引数は[研究エンジンの説明](../research-engine/README.md)を参照。

MCPは科学的な解釈やサブエージェントの実行を自動では行わない。依頼と作業記録を永続化し、対話の再開時に続きから進める。常駐巡回やアプリ終了後の自動研究は、別途実行基盤を追加する場合の機能とする。

## 既存データを保ち、ダスト輸送から移行を確かめる

研究ストアは形式2で、レコードの種類を明示的に検査する。形式1の既存データも読めるが、書き込みの前に明示的な移行が必要である。旧レコードのID・改訂・根拠・PDFハッシュを保持し、移行前にSQLiteバックアップを作る。形式1のアプリが形式2へ書き込むことを防ぎ、復旧には移行前のバックアップと対応版を使う。

ダスト輸送の実データは2026年9月15日に移行した。既読12版・145ページの解析を、分野の入口、帯電、離脱、飛行、地形、観測、詳細比較、研究史、残件など13ページ・78節へ再編した。全78主張・22関係を参照し、旧489改訂・416現行記録と既存ファイルを保持している。研究フォルダの`notes/wiki-index.md`がMarkdownの入口、`data/wiki-migration.json`がバックアップ先と適用記録である。

移行は既存の解釈を整理する作業であり、新たな科学的検証ではない。節は`migration_unverified`として保存し、探索・関係検証の未完了も残した。画像・内部リンクの参照先と出力の一致を検査したが、最終アプリ画面とVS Code標準Markdownプレビューの確認は未実施である。

| 実装の順序 | 到達する状態 |
| --- | --- |
| ページと根拠 | 固定ID、節、改訂、根拠付き本文を保存し、アプリで現在版を読める |
| 比較と案内 | 別名・分類・逆参照から項目を探し、同じ固定結果から比較表を表示できる |
| 追加調査と再検討 | 根拠の変更と新しい資料の両方から更新候補を作り、依頼をページ更新まで追える |
| 移行と運用確認 | 既存のダスト輸送データを保持し、追加サーベイの前後で理解と根拠の変化を説明できる |

初期実装の受け入れ条件は次のとおりとする。

- 同じ問いへの追加調査で、同じページが改訂され、変更理由と根拠を確認できる。
- 一つの論文の異なる条件を別の結果として比較し、引用関係のない文献も比較に含められる。
- 重要な判断から固定改訂の根拠、PDFページ、図表へたどれる。数式と画像は書き出し後も表示できる。
- 根拠の変更に依存する節へ再検討が伝わり、案内リンクだけのページには伝わらない。
- まだリンクのない新規論文も関連付け待ちに残り、未統合のまま失われない。
- 過去版を開いたときに、採用した表や根拠が現在版へ勝手に置き換わらない。
- 人間の編集と並列担当の結果が競合したら保持・照合し、中断後も残りの作業を再開できる。
- 未読、未取得、未解決を区別し、wikiの整備状況と文献探索の網羅性を別に確認できる。
- 概観を短くしても、論点別レビュー、条件別の結果、反証、導出、原資料への接続が保たれる。
- 対話で採用した訂正や研究条件が永続記録へ戻り、次の依頼で同じ説明を入力し直さずに済む。

この設計の実装時には、[アプリの利用手順](app-research.md)、[全文読解](full-paper-reading.md)、[研究史](research-history.md)、[ワークスペースの指示](../templates/workspace/AGENTS.md)を、実装された範囲に合わせて更新する。
