# 引用の外まで探索し、主張の根拠と未確認事項を残す

この手順は、研究ワークスペースで先行研究を調べる読解担当と調整役が使います。
人手では追い切れない規模の網羅性と、主張の根拠を繰り返し確かめる詳細さを目標とします。
重要な主張を支える原論文と、その後の検証・反論・条件変更をたどり、引用関係のない関連研究も独立に探します。
初回は探索範囲を決める節から引用・独立検索の節まで読み、以後は取得・読解・比較・終了判定の各節を参照してください。

これはホストが実施する運用です。研究MCPにはノート・根拠・主張・関係の保存、固定改訂の参照、読解計画があります。
`search_records`は部分一致検索、`trace_record`は登録済み参照を遡る操作です。
意味検索、被引用論文の収集、自動巡回、下記の補助台帳の取り込みは実装されていません。
検索や判断は利用可能な外部検索と読解担当が行います。既存APIの仕様は[研究エンジン](../research-engine/README.md)を参照してください。

## 探索範囲と検索の組合せを先に記録する

何の判断を更新したいかを問いとして書き、対象分野・隣接分野、期間と基準日、対象版、文献種別、言語、採否条件を定めます。
制限を設けない項目も「制限なし」と記録します。後から範囲を変える場合は、理由と影響する検索を残します。
総説は用語や候補を集める入口に使い、科学的な結論の根拠には原論文を確認します。

検索表の一枠を「概念の組合せ × 情報源 × 期間・フィルター」とし、次の語群を交差させます。

| 語群 | 展開する内容 |
|---|---|
| 対象・物理 | 対象物、現象、機構、旧称、隣接分野での呼称、綴り・略語・言語の違い |
| 方法・条件 | 実験装置、理論・数値手法、近似、材料、スケール、境界条件 |
| 観測量・結果 | 測定量、指標、別の定義、再現実験、反例、検出されなかった効果 |

各枠に検索式、情報源、実行日、絞り込み、確認した範囲、結果件数、新規候補、次の検索を残します。
検索結果の続きが未確認なら、その位置を保存します。結果ゼロ、実行不能、未実行を区別してください。
同じ概念が別名で見つかったら語群を更新し、影響する枠を再実行します。

## 引用と独立検索を繰り返し、未処理候補を更新する

起点論文ごとに参考文献を収集し、被引用論文も利用可能な索引で調べます。引用一覧の情報源と確認日を残し、
新たに重要と判断した論文でも同じ探索を繰り返します。引用深度は記録しますが、「一段先まで」「11本まで」を終了条件にしません。
どの主張の由来、反証、適用範囲を確かめるための候補かを書き添えます。

引用探索と並行して、検索表によるキーワード検索、利用可能なら意味検索を行います。
共通する方法・データ・装置・観測量、著者や研究群、近接する問いからも候補を探してください。
引用網との接続が弱い研究群や、用語・方法の異なる隣接分野も独立した探索対象にします。
意味検索の類似度は採用根拠にせず、本文で関係を確かめます。引用のない論文も採否条件に合えば同じ読解工程へ渡します。
引用された事実だけで依存や支持を認定せず、非引用から影響の不在を断定しません。

候補はDOI、次いで題名・著者・年・永続IDで照合し、異版の対応を確認します。
候補台帳には発見経路、採否と理由、優先度、対象の問い、取得・読解状態、次の担当作業を残します。
優先するのは結論を左右する原典、対立する結果、重要な条件差、未検証の橋渡しです。
低優先、範囲外、重複、未読も理由を残し、見つけた記録を削って見かけの網羅性を上げないでください。

## 所蔵を確認してから全文を取得する

取得順は **ローカルのGoogle Drive／Paperpile → 出版社 → プレプリント・著者最終稿・著者公開版 → 未取得BibTeX台帳** とします。
最初に読み取り専用索引をDOI・題名・著者で検索し、所蔵済みPDFと既存の取得記録を照合します。
同じ版が利用可能なら再ダウンロードせず、ハッシュを確認して使います。アクセス失敗や索引未更新を未所蔵とみなしません。

出版社本文と補足資料・訂正を確認し、取れなければ対応する公開版を探します。
代替版は出版版との同等性を推定で埋めず、重要な式・図表・結論の差分確認を残します。
未取得文献は書誌、必要な理由、試したURL・日付・結果、代替版、次の行動とともに
`candidates/literature-access.bib`と取得台帳へ記録します。既知の状態を引き継ぎ、取得済み・読了・購入判断を分けます。
同期済みPDFやPaperpile出力は変更しません。詳細は[取得台帳の手順](research-history.md)に従います。

## 論文単位で全文を読み、検証可能な主張に分ける

探索、取得、全文読解、主張整理、関係比較、科学的監査は別々の永続待ち行列で管理します。
調整役は検証済みの成果を順次統合します。
依存先が揃った作業を順次渡し、読解担当の全員が終わるのを待たず、空いた枠へ次の文献を割り当てます。
並列数は、調整役と他の実行中作業を考慮したホストの現在の空き枠で決めます。特定の上限値を恒久的な能力とみなしません。

一つのPDF版に一人の担当を割り当て、SHA-256、総ページ数、保存先ノートを固定した永続`ReviewTask`を使います。
担当の確保と再開は[並列レビュー](parallel-review.md)に従い、同じハッシュの本文・画像キャッシュと読了ノートを再利用します。
本文、参考文献、付録を含む全ページを読み、図表・数式・キャプションと補足資料を確認します。
補足資料が別ファイルなら版とハッシュを記録し、未取得・未読・判読不能を本文の読了状態に隠しません。

重要な主張ごとに、検証可能な一つの内容へ分けて条件と根拠を保存します。
著者の測定、計算、推定、仮定、機構の提案、読み手の推論を分けてください。
各主張にはPDFページ・節・図表・式番号、SourceとEvidenceの固定改訂を付けます。
式は記号、単位、符号、半径と直径、近似、初期・境界条件を照合し、結論を左右する短い計算を再計算します。
測定値と推定値、不確かさとばらつき、測定限界、失敗した再現実験も本文に報告されていれば残します。
抽象的な要約だけに縮めず、判断を後から再検証できる値・条件・導出過程を保持します。

主張が先行文献を根拠にしている場合は、その引用先を取得・全文レビューしてから確定的な知見へ採用します。
引用先未確認の段階では「当該著者による紹介」と原典未確認を明記し、支持の鎖を完成扱いにしません。
総説や要旨の記述で原論文の読解を代用せず、研究仮説はClaimと混ぜずQuestionへ置きます。
重要な図表は文書配下に保存して画像として埋め込み、保存後の対象プレビューで数式と画像を確認します。

## 重要な関係を条件ごとに比較し、独立に監査する

全論文の組合せを浅く埋めると、重要な関係の検証が遅れます。
共通の主張・方法・データ、明示された継承や批判、矛盾の候補から関係の待ち行列を作り、結論への影響で優先します。
候補に挙がったが比較対象にしない組合せも、判断に影響しない理由や未確認の理由を記録します。

各関係の詳細記録には、双方の論文・主張・版、比較する問い、揃えた条件、維持された点、変更された点、
支持・拡張・批判・条件差の根拠、反対の証拠、未解決の差、次の確認を残します。
単位や定義を換算した場合は変換式と元の値を保存してください。
材料・粒径・照射・装置・測定量などの違いを検討し、条件が揃わない結果を即座に矛盾と呼びません。
効果が出なかった結果や再現失敗は報告された範囲で扱い、記載の不在から反証を作りません。

関係の出典区分は、著者が明記した根拠を確認したときだけ`author_explicit`、読み手による比較は`analyst_inference`です。
既存Relationの種類は`extends`、`uses_method`、`supports`、`challenges`、`differs_in_conditions`です。
単なる引用記録を無理にこれらへ割り当てず、探索台帳に保持します。

重要な接続と対立する結果は、最初の読解担当とは別の監査担当が双方の原文に戻って調べます。
監査では支持する根拠に加え、別の説明、反例、条件の混同、原典の読み違いを積極的に探します。
指摘ごとに根拠位置、修正または維持する理由、残る疑義を保存します。
担当は個別成果物を返し、共有の台帳・年表・Question・Topicは調整役だけが更新します。
DB更新には`expected_revision`を使い、人の追記を保持します。競合時は再読・統合し、改訂番号だけを更新して上書きしません。

## 探索の進捗は、分母と未処理事項を添えて保存する

以下は外部研究ワークスペースに置く任意の補助ファイルです。既存SQLite形式やMCP型への追加項目ではありません。
採用するJSONには`format_version: 1`、調査基準日、範囲、更新履歴を持たせ、互換性を壊す変更では版を上げます。

| 保存先 | 残す内容 |
|---|---|
| `data/review-coverage.json` | 宣言した範囲、検索表、各指標の分母と実績、未確認事項、終了判定 |
| `candidates/research-frontier.json` | 未処理の文献・関係、発見元、優先度、採否理由、担当、再開条件 |
| `reports/relations/<id>.md` | 重要な関係の比較条件、両側の根拠、監査所見、判断の改訂 |

非読解作業のキューにも、次の共通項目を持たせます。これはホストが更新する補助台帳の契約であり、MCPの新しい型ではありません。

| 項目 | 内容 |
|---|---|
| `id`, `task_type`, `target`, `priority`, `why` | 安定した作業ID、工程、対象、優先度と採否・必要性の理由 |
| `status`, `owner`, `started_at`, `attempts` | 状態、実際の担当、開始日時、試行履歴。未割当は担当なし |
| `input_refs`, `input_hashes`, `depends_on` | 判断時点のID・改訂、PDFや入力ファイルのハッシュ、前提作業ID |
| `outputs`, `completion_rule`, `invalidated_reason` | 成果物とハッシュ、受理条件、訂正等で再検証が必要になった理由 |

依存先待ちは`waiting_dependencies`、配布可能は`ready`、実際に担当を確保した作業だけ`running`にします。
担当は入力の固定参照・ハッシュと成果物を返し、調整役がそれらと受理条件を照合してから`completed`へ進めます。
失敗や判断不足は`needs_followup`、外部の取得制限は`blocked_external`、意図した保留は`deferred`、理由を付けた除外は`excluded`です。
入力変更で再点検する作業は`needs_revalidation`とし、過去の成果を残したまま新しい統合への採用を止めます。

再開時は担当の実行状況と入力の現在版を確認し、動いている作業を二重配布しません。
担当が終了・消失していれば未保存の成果を確認し、試行を閉じてから再割当します。経過時間だけで担当消失と判定しません。
訂正・新版を見つけたら固定入力と依存先を逆引きし、影響する主張・比較・監査・統合を再検証対象にします。
`trace_record`は逆引きを実装していないため、ホストが台帳の依存先、またはページ送りで取得したレコードの参照を照合します。
影響範囲を確定できない間は候補範囲を保留し、古い入力で返ってきた成果は新しい統合へ受理しません。
対象版を意図的に固定した歴史記録はその版の判断として保持し、現在版の評価とは分けます。

これらのJSONは調整役だけが更新し、作業者は個別成果物を返します。更新前に読み込んだファイルのハッシュを再確認し、
競合時は再読して統合します。補助台帳にDBの改訂競合検出が自動で働くわけではありません。
PDF読解には既存の`ReviewTask`と`expected_revision`を使い、補助台帳だけで読解の確保・完了を代用しません。

進捗には、起点論文の参考文献収集数／対象数、候補の採否・取得・全文読解状態、引用深度別の残件、
検索枠の実行・未実行・失敗、PDFやノートの旧版参照、関係待ち行列の解決・未解決数を残します。
各分母の定義と重複の扱いを明記します。「対象候補の何件を読了したか」は示せますが、
分野全体の文献数や再現率が不明なまま「分野の90%を網羅」とは書きません。
新しい版や訂正を見つけたら影響する主張と関係を再確認対象にし、過去の根拠と判断を保持します。
新着論文の採用時も、関連する主張・関係・統合結果をたどって再検証を起票します。影響のない保存済み結果は再利用します。

## 探索の飽和と、予算による中断を分ける

確認の区切りでは、宣言した全検索枠を実行したか、高優先の文献・関係が処理済みかを点検します。
参考文献収集・被引用探索の対象数と完了数を照合し、起点論文および反復探索で採用した対象の展開作業が残っていないことも確認します。
発見キューの各対象には採否と理由が必要です。採用した対象の未展開・途中の検索結果・原典未確認の依存が残る間は、範囲内の探索完了としません。
未取得などで進めない項目は、試行記録・結論への影響・再開条件を伴う未解決事項として残します。
検索語や方法を広げても新たな関連候補が得られないかを確かめ、その試行も保存します。
検索機能を利用できず未実行の枠がある場合は、範囲内の探索完了を宣言しません。

これらを満たした時点は、指定範囲での「運用上の探索飽和」です。未知の文献が存在しないことの証明ではありません。
件数・時間・予算の上限に達した場合は中断とし、完了とは報告しません。
再開時は同じ候補台帳と固定根拠から続け、次に読む優先文献と、それにより変わり得る判断を明記します。
手順だけで判断できない点は調整役へ戻し、具体的な研究上の疑問はQuestionまたは未処理台帳へ残してください。

用語：候補台帳は発見済み文献の採否と作業状態、未処理候補（frontier）は次に調べる文献・関係、
固定改訂は判断時点の根拠を指定するIDとrevision、探索飽和は指定した探索方法で追加候補が得られなくなった状態を指します。
