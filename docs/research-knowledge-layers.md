# 原資料・読解記録・研究wiki・対話をつなぐ

研究wikiを現在の解析・解釈の正本にし、論文ごとの読解記録を再利用する中間成果として保持する。証拠は原資料までたどれる形で保存する。wiki全体では分野の大規模レビュー論文に相当する網羅性と詳しさを目指し、読者が必要な深さまで進めるようにする。

この文書は[研究wikiの設計](research-wiki.md)の一部で、情報の役割、保存と再利用、追加調査での更新、階層ごとの詳細度を定める。実装では同じ研究DBにwikiを加え、従来の論文ノート・主張・根拠を保持する。各機能の実装範囲は設計文書の冒頭を参照。

## 正本を、情報の役割ごとに決める

原論文、論文ノート、wikiは異なる内容の正本を持つ。wikiへ統合しても、原資料と読解の経緯を保存する。論文の主張自体も検証対象なので、出典が存在することと、その主張が妥当であることを分ける。

| 層 | 保存する内容 | 正本として扱う範囲 |
| --- | --- | --- |
| 原資料 | PDF、補足資料、データ、訂正、版とハッシュ、取得元 | その資料に何が記載・記録されているか。Paperpileは読み取り専用 |
| 抽出素材 | ページ別テキスト、OCR、ページ画像、切り出し前の素材 | 再処理用の素材。抽出誤りを含み得るため、機械抽出だけで検証済みの証拠にしない |
| 読解・解析の中間成果 | 論文ノート、全ページの確認状況、主張、条件、引用箇所、式の照合、論文間の比較、監査所見 | 各資料をどう読み、どの根拠から何を取り出したか |
| 研究wiki | 概念や問いごとの統合的な解釈、成立条件、対立、比較、研究史、残る課題 | 調べた範囲での現在の理解と、採用した判断の理由 |
| 対話の文脈 | 今の問い、目的、制約、選択したwiki節、必要な根拠 | 今回何を判断・調査するか。採用した知見や制約は永続記録へ戻す |

これは一方向の要約処理ではない。対話からwiki、比較記録、論文ノート、原図へ必要に応じて戻る。追加調査で中間成果を更新し、その影響をwikiの解釈へ反映する。

論文ノートのMarkdownは、自由な読解を残せる中間表現として有用である。式の導出、図の読み方、局所的な留保など、共通の入力欄だけでは扱いにくい内容を保存できる。ただし、関係や更新の追跡に使う情報には、固定ID、改訂、条件、出典位置を付ける。Markdown本文と構造化した参照を組み合わせ、書式だけに依存しない。

wikiの節を別ページで参照するときも、採用した原資料への参照を引き継ぐ。wikiと、それを要約したレポートを別々の独立した証拠として数えない。wikiの文章を再び抽出してClaimに登録し、元のwikiを支持する循環を作らない。

独自の計算や実験から新しい結果が得られた場合は、生データ、手順、コード版、実行条件、結果を研究成果物として保存する。wikiにはその解釈を記す。現在の論文PDF用Sourceへ実験記録を無理に割り当てず、対応する資料形式と検査を追加する。

## 詳細レビューを再利用し、重複した要約を減らす

論文の全文を毎回読み直すコストを減らすには、初回の詳細な読解を残す必要がある。wikiの現在の問いに採用されなかった結果も、後から別の問いで必要になる。文献ノートには、wikiへ採用した範囲に限らず、その資料を再利用するための詳細を残す。

| 成果物 | 保持・生成の方針 |
| --- | --- |
| 原PDFと資料の版 | 原資料へのアクセスを維持する。論文ノートで代替したことにしない |
| 論文ノート、主張、根拠、比較、監査 | 意味のある改訂を保持する。完了済みの読解を、同じPDF版で再利用する |
| wikiの現在版と履歴 | 同じページを育て、採用した根拠と変更理由を保持する |
| 調査ログと未処理台帳 | 検索範囲、結果、採否、取得失敗、中断位置など再開に必要な情報を残す |
| 毎回の総合レポート | 必須にしない。通常はwikiの更新と変更点の説明で完了する |
| 提出・共有用レポート | 必要時にwikiから生成する。対象ページ・改訂・基準日を固定した成果物として保存する |
| DBから生成したMarkdown | 閲覧・持ち出し・外部プレビューの必要に応じて出力する。DBと別々に編集する正本を作らない |
| 再生成できる抽出キャッシュ | 元資料、抽出設定、参照関係を確認して整理できる。ただし根拠に固定したテキストや図は除く |
| 対話の一時的な要約 | 会話の継続用に使う。採用された内容の唯一の保存先にしない |

同じ内容を再登録して改訂を増やさず、同じPDFの取得・抽出を共有する。画像は内部では共有できるが、Markdownを持ち出すときは必要な画像を文書配下へ同梱する。複製の少なさと、持ち出した文書が単独で読めることを両立させる。

整理の基準は、ファイルの拡張子ではなく内容と来歴である。手書きノート、独自の導出、出典を整理した表は、wikiに同じ情報があるかを確認する前に削減対象としない。既存の`notes/`や`reports/`には、独立した内容を持つファイルもある。

移行時は、各ファイルの内容を保持する先の記録・改訂と対応させる。手修正、参照元、図表、再生成可能性を確認してから、重複する表示をまとめる。履歴へ固定されたファイルは維持するか、同じ内容へ解決できる参照を残す。単に古い、wikiに一度使ったという理由では削除しない。

## wiki全体を大規模レビューの詳しさにする

目標は、主要な機構・手法・結果・競合する説明を網羅し、それぞれの条件、導出、限界、発展関係まで検討できる内容である。参考文献数や総文字数だけを完成条件にしない。既存レビュー論文は論点や用語を探す入口にもなるが、それが省略した研究群、反例、非引用の関連研究も探索する。

| 読む深さ | ページの役割 | 保持する内容 |
| --- | --- | --- |
| 分野の入口 | 対象と主要な問いを把握する | 研究の見取り図、現在の理解、重要な対立、各論への入口、探索範囲 |
| 論点別のレビュー | 一つの現象・問いを詳しく理解する | 機構、主要な説明、研究の変遷、実験・理論の対応、残る問題 |
| 条件・方法ごとの解析 | 結果の成立範囲と差を検討する | 比較表、条件差、観測量の定義、反例、再現、各判断の根拠 |
| 導出・検証の詳細 | 判断や計算を追試する | 仮定、途中式、単位、感度、元の値、図の読み方、監査所見 |
| 個別資料の読解 | 出典の文脈を確かめる | 論文ノート、全ページの確認記録、根拠箇所、原図と原PDF |

上位ページの説明を短くしても、下位の詳しい解析を維持する。概要に使わなかった反対の証拠や条件差も、適切な節からたどれるようにする。下位ページへの移動は補助的な参照だけでなく、レビュー本文の続きを読む操作として扱う。

次はダスト輸送における階層の例であり、各論点についての科学的な結論や読了状況を示すものではない。

```text
ダスト輸送
├─ 帯電
│  ├─ 機構とモデルの比較
│  └─ 条件別の結果と検証
├─ 表面からの離脱
│  ├─ 力・接触状態・初期条件
│  ├─ 照射条件ごとの実験結果
│  ├─ 理論の予測と観測の対応
│  └─ 対立する説明と判別に必要な研究
├─ 浮上後の運動と輸送
└─ 観測から何を判定できるか
```

この階層に加えて相互参照を持つ。例えば帯電モデルから離脱の比較へ、観測手法から同じ手法を使う複数の論点へ移動する。共有する定義や長い導出は一つの項目へまとめ、各ページはその適用の仕方を説明する。

独立した問い・比較条件・方法として読めるまとまりでページを分ける。短い注意書きまで別ページにして文脈を失わせず、長い一覧は条件や方法で絞り込めるようにする。本文内には次の論点へのリンク、現在地、参照元を表示する。初心者向けの入口と、研究者が原式へ直接進む入口の両方を用意する。

説明を簡略化した上位ページには、成立条件と重要な留保を残す。詳細ページの見出しだけをリンクして、上位では無条件の結論にしてしまう編集を認めない。下位で解釈が変わったら、その解釈を要約する上位ページにも再検討を伝える。

## 網羅性と詳細度を、論点ごとに確認する

分野全体を一度に「完成」と判定せず、論点ごとに対象範囲と未処理事項を持つ。検索が行き届いているか、論文を読み終えたか、関係を比較したか、wikiへ統合したかを別々に確認する。

| 点検する範囲 | 確認すること |
| --- | --- |
| 論点の網羅性 | 主要な問い、競合する説明、隣接分野、異なる呼称が探索対象に入っているか |
| 文献の探索 | 引用・被引用・独立検索の経路、対象期間、未確認の検索結果を記録しているか |
| 一論文の詳細度 | 方法、条件、結果、全図表、数式、限界、付録・補足、先行研究への依存を確認したか |
| 論文間の解析 | 共通条件、差分、継承・批判、共有データ、独立性、反対の証拠を検討したか |
| 統合の詳細度 | 説明の根拠、適用範囲、未解消の対立、導出へ進めるか |
| 未処理事項 | 未取得・未読・未比較・未監査・未統合がどこに残り、判断へどう影響するか |

wikiの冒頭には、その論点の理解を左右する未処理事項を表示する。確認した文献が増えたことを、そのまま解釈が確定したことにはしない。重要な違いを統合できない場合は、比較と疑義を詳しく残し、現在版に確認した範囲を明記する。

## 対話には必要な根拠を渡し、得られた判断を保存へ戻す

自然文の依頼では、まず対象のwiki項目と問いを探す。既存の解釈で答えられる範囲、再点検が必要な箇所、新たに調べる範囲を確認し、必要な中間成果と原資料を読む。現在版のwikiは検索の入口として使い、未統合の資料と未処理台帳も合わせて調べる。

対話へ渡す情報は、問い、目的・制約、対象ページと節の改訂、適用条件、支持・反対の根拠、残る作業への参照を含める。長い原文をすべて最初に詰め込まず、必要な箇所を追加取得できるようにする。情報を省いた場合は取得範囲と続きを示し、要約だけで検証したことにしない。

会話が長くなっても、重要な制約、採用した判断、未解消の疑義、次の作業を研究フォルダへ保存する。人間の発言から研究条件を受け取ることと、科学的な主張を裏付けることは別である。未検証の提案はQuestionや点検待ちの記述へ保存し、出典付きの結果に変換しない。

全ページ読解が済んでいる同じPDF版は、保存済みのノートと根拠を再利用できる。重要な解釈の変更では、必要な原文・式・図に戻って点検する。新規・未読の論文は、既存の全文読解手順に従う。短い対話の回答を得るために、未読資料の要旨を全文レビュー済みとして扱わない。

wikiに見当たらないことは、研究が存在しない証拠にならない。必要なら文献ノート、未統合の主張、未処理候補、外部検索へ探索を広げる。検索の結果を使ってページの範囲や別名も更新する。

## 追加調査で、各層をどう更新するか

例えば「離脱条件について、既存の説明を変える研究がないか調べて」という依頼なら、wikiの対象節と現在の根拠を固定して作業を始める。新しいPDFは取得版として保存し、論文単位の全文レビューを行う。その結果を既存の条件・主張と比較し、判断を変える場合は根拠と監査所見を付ける。

変更は該当する比較・詳細ページへ反映し、その説明を使う論点別レビューと分野の入口を点検する。最後に対話では何が変わり、どの条件では以前の判断を維持し、何が残ったかを説明する。変更が不要だった場合も、照合した資料と理由を残す。新しい総合レポートの作成は必須にしない。

移行と実装の受け入れでは、次を確かめる。

- 一つの判断について、wikiから中間成果と原資料へ戻り、改訂後も当時の根拠を再表示できる。
- wikiの文章や派生レポートを根拠として循環させず、独立した証拠の数を水増ししない。
- 同じ資料の全文レビューを再利用しつつ、新版・未読資料・未統合の結果を見落とさない。
- 詳細ページを分割・改訂しても、上位の留保、相互参照、原図、導出への接続を保つ。
- 会話で採用された訂正や制約を、次回の対話から検索・再利用できる。
- 重複する出力を整理するときに、独自の内容、人間の追記、固定された参照を失わない。
